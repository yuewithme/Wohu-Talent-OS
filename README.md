# 沃虎人才 · 招聘助手

Chrome / Edge Manifest V3 浏览器插件。0.2.0 通过列表明文响应、当前候选人的 Vue 数据、详情 DOM 摘要及 Canvas 绘制前的文字合并采集，在插件中预览，并按设计文档的 API 契约对接招聘系统。

## 安装

1. Chrome 打开 `chrome://extensions`，或 Edge 打开 `edge://extensions`，开启“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择本项目的 `dist` 文件夹。
3. 将“沃虎人才 · 招聘助手”固定到工具栏。
4. 更新构建后，在扩展管理页点击插件的“重新加载”，再刷新 BOSS 页面。提前加载的采集器才能观察首次请求和绘制。

分发文件为 `release/wohu-talent-0.2.0.zip`。先解压，再选择包含 `manifest.json` 的目录加载。

## 使用

1. 登录 BOSS 招聘端，进入“推荐牛人”，打开一位候选人的详情。
2. 点击工具栏中的插件图标，再点击“读取当前候选人”。
3. 查看基本资料、工作职责、教育、项目、采集原文与完整度说明。没有后端也能完成这一步。读取时可能短暂调整详情显示高度，结束后自动恢复。
4. 如果要导入，先在设置页填写招聘系统根地址、组织 ID、访问令牌并保存验证。连接信息变更会清除当前临时预览，请重新读取。
5. 多来源仍未读取到姓名时，导入前对照页面补充姓名，点击“确认姓名”。
6. 获取开放岗位、选择岗位、检查重复、明确选择处理方式、勾选确认后提交。
7. 提交结果不明确时使用“刷新导入状态”或“使用原请求重试”。重试沿用原幂等键。关闭弹窗不会清除待确认的提交编号。

## 当前读取范围

- 已实测页面：`/web/chat/recommend` 内同源 `/web/frame/recommend/` 的候选人详情，正文位于 `/web/frame/c-resume/`。
- 基本资料：姓名、年龄、工作年限及原始年限描述、学历、求职状态、个人简介；本人期望与最近关注/平台推荐方向分开保留。当前所在城市没有可靠来源时留空。
- 工作经历：公司、职位、起止时间、职责与工作技能标签。详情正式公司名与卡片职责仅在职位、开始日期和公司名称能够唯一对应时合并。
- 教育和项目：学校/项目名、专业/角色、学历、起止时间；能定位到对应段落时补充正文。未结构化的段落仍保存在采集原文中。
- 仅对“至今”的工作记录填写当前公司/职位，已结束的经历不推断为当前任职。
- 采集原文保留 Canvas 绘制文字；每个字段附来源、路径、候选人标识和批次证据。接口列表缓存最多 50 条、10 分钟，仅用于匹配当前候选人。
- 晚注入时尝试通过页面已有的同一候选人加载流程补取首屏。通过临时扩展画布显示高度覆盖虚拟正文，恢复原布局后返回结果；超过高度/字符限制或未绘制时明确报告部分覆盖。
- 不做 OCR，不识别图片、视频、附件内部内容。画布区域覆盖不等于折叠段落已展开；个人简介和工作职责优先保留结构化原文，其他折叠内容可能需要人工展开后重读。不保证所有页面版本的全部字段。
- 仅观察已发生的列表明文响应，不自行构造带认证参数的 BOSS 请求，不破解详情加密数据，不自动翻页或联系候选人。
- 页面结构变化、不可见详情、多个详情同时显示或关键身份不一致时停止读取。采集及提交前复核候选人 ID、绘制批次和详情指纹；Canvas 顶部姓名还需与当前候选人一致。

其他页面类型尚未验证，显示不支持。采集逻辑位于 `src/adapter/pipeline.ts`、`page-state.ts` 和 `sources.ts`，DOM 摘要适配仍位于 `boss.ts`。

## 后端连接契约

本项目**不包含后端、数据库、飞书同步服务或模拟服务**。未提供真实后端，目前尚未完成真实 API 联调。

服务根地址使用 HTTPS，例如 `https://ats.example.com`。本机开发允许 `http://localhost:端口` 和 `http://127.0.0.1:端口`。不要填写 `/api/v1`，插件会自动添加。

| 接口 | 插件用途 |
|---|---|
| `GET /api/v1/me` | 登录、组织、导入和合并权限 |
| `GET /api/v1/jobs` | 开放岗位搜索与分页 |
| `POST /api/v1/candidate-imports/preview` | 校验与去重预览 |
| `POST /api/v1/candidate-imports/commit` | 人工确认后的幂等提交 |
| `GET /api/v1/candidate-imports/{id}` | 恢复查询与飞书同步状态 |
| `GET /api/v1/candidates/{id}` | 重复候选人摘要 |
| `GET /api/v1/candidates/{id}/applications` | 已有应聘关系 |
| `POST /api/v1/extension/diagnostics` | 用户主动发送的脱敏诊断 |

请求携带 `Authorization`、`X-Org-Id`、`X-Request-Id`、`X-Client-Type`、`X-Client-Version`；Commit 另携带 `Idempotency-Key`。响应契约见 `src/shared/contracts.ts`。合并要求 `/me` 返回 `candidate:merge` 权限，所有写入动作还受 `allowed_actions` 限制。

`/me` 可选返回 `extension_config.boss_adapter_enabled=false` 紧急停用采集，或 `extension_config.minimum_version` 强制最低版本。`feishu_sync.record_url` 可选提供已同步记录链接。未提供这些可选字段时仍支持文档中的标准响应。

幂等、租户隔离、去重判定、正式 Candidate/Application 的创建和飞书同步由后端保证。插件不会直接连接飞书或数据库。

## 数据与权限

- 使用 `activeTab`、`scripting`、`storage`、`alarms` 和 BOSS 网站权限；在匹配页面的 MAIN 环境于 `document_start` 加载采集器。API 域名仅在保存连接时按具体域名请求授权；后台网络请求还必须匹配配置中的完整 origin（含端口），禁止重定向。
- 招聘系统 Token 和已确认的候选人草稿保存在插件会话存储，页面脚本不可访问 Token。采集器短期使用页面内存，来源数据仍视为不可信；后台校验后才保存草稿。浏览器重启后需要重新登录；预览默认 30 分钟过期。
- 本地持久化保存连接配置和待确认提交的编号、操作、岗位、幂等键、组织/用户 ID，不保存简历正文或 BOSS 登录凭证。
- 诊断默认关闭，启用后仍需手动点击上报；仅发送固定字段键、散列指纹和错误码。

当前真实页面检查用于验证多来源采集与身份对应，不代表已达到原设计文档的 20–50 份样本覆盖或统计准确率要求。0.2.0 新增字段与多来源证据尚需后端接入方联调确认。
