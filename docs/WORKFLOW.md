# HR 招聘工作流

## 1. 岗位准备

使用 `job-description-writer` 产出岗位说明，沉淀岗位职责、硬性要求、加分项、BOSS 筛选条件和面试维度。岗位要求是评分规则的输入，不把某一个岗位写死。

## 2. 候选人获取

BOSS 数据优先走本包内置 Kimi BOSS adapter：`hr-recruiting-orchestrator\scripts\kimi-boss.ps1`。它复用已登录页面读取招聘端数据，当前实测不触发 BOSS 硬重载。OpenCLI 只作为 fallback，必须通过 `opencli-boss-locked` 串行执行，执行后解绑。

## 3. 简历来源读取

简历分为两类，入库时必须分开：

- 电子简历：BOSS 在线简历面板，由 `kimi-boss.ps1 resume <uid>` 读取，写入 `电子简历*` 字段。
- 附件简历：PDF/Word 等上传文件，先通过 BOSS 或飞书下载到本地；PDF 统一交给 `pdf` skill 做解析、页面检查和摘要，写入 `附件简历*` 字段。

招聘总控不重新实现 PDF 解析器，也不把 BOSS 页面文本当作附件简历解析结果。

## 4. 飞书 Base 同步

飞书 Base 是业务主库。写入前先读字段列表，字段名以 Base 返回为准。电子简历优先写入 `电子简历姓名`、`电子简历工作经历`、`电子简历教育经历`、`电子简历原始JSON` 等细分字段；附件简历写入 `附件简历文件名`、`附件简历文本`、`附件简历摘要`、`附件简历解析状态` 等字段。原始 JSON 可保存为证据，本地文件只做临时和排障用途。

## 5. 筛选评分

按岗位要求生成评分标准，写入分数、评级、点评、风险点和面试关注点。Top 候选人补充结构化点评。

## 6. 面试方案

使用 `interview-kit-builder` 的结构生成专属问题表，优先导入为飞书在线文档，把链接写回 Base。附件字段不可稳定写入时，不强塞附件字段。

## 7. 候选人触达

`send`、`greet`、`batchgreet`、`invite`、`mark`、`exchange` 都是外部副作用。执行前必须确认对象、动作和内容；执行后写回 Base 动作、时间、结果和失败原因。
