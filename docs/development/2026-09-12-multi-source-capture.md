# BOSS 多来源候选人采集开发日志

## 任务目标

根据用户本次授权，直接改造浏览器插件的采集链路，补齐候选人已展示、可获取的信息。优先明文 Network 与 Vue 运行时，保留 DOM 核对，Canvas 绘制明文补充详情；不实施 OCR、后端或飞书服务。所有数据必须归属同一候选人，未覆盖区域、缺失字段和冲突必须明确表达，不能将部分采集声称为全量。

## 实施计划

1. 新增受限的 MAIN 页面采集器，提前观察已发生的列表响应和简历 Canvas 绘制；支持运行时补取，限制内存与生命周期。
2. 按当前候选人身份和渲染批次归并来源，补充基本资料、工作职责、教育、项目与原文；保留最近关注和期望的语义区别。
3. 扩展字段证据、覆盖状态和现有预览，后台继续承担鉴权与严格校验；复用现有导入流程。
4. 真实页面验证字段、候选人切换、关闭详情、Canvas 全区域绘制采集和正式扩展加载；运行必要的类型检查、针对性验证和构建打包。

## 完成标准

- 当前候选人的姓名、年限、学历、个人简介和可用工作职责能够正确读取，并标记来源。
- Canvas 补充具有当前候选人和绘制批次校验，去除重绘重复，覆盖范围可解释；不能覆盖时保留明确提示。
- A/B 切换与关闭后不返回旧候选人数据；最近关注不冒充本人期望；来源冲突不静默丢失。
- 真实页面和正式扩展运行通过验证后交付新包；未通过或未覆盖项目如实记录。

## 完成结果

- 已交付 v0.2.0：Network、Runtime、DOM、Canvas 输出字段证据，由 Resolver 按候选人身份及置信度归并；冲突、来源和覆盖状态保留在采集结果中。
- MAIN document_start 观察同源推荐列表明文响应及简历绘制；列表仅缓存投影后的字段，不保存鉴权参数或完整响应。运行时补取解决安装过晚、早期请求已结束的情况。
- 姓名、年龄、年限、学历、简介、工作职责与标签、教育、项目及绘制原文进入现有预览。最近关注与真实期望分开，缺失联系方式或当前城市不推测代填。
- Canvas 使用 fillText/strokeText 绘制前明文，不使用 OCR。临时扩大详情容器，使虚拟 Canvas 绘制完整区域；采集后恢复样式。短简历复用已完整绘制的文本，按清屏与候选人绘制批次去重。首次注入错过绘制时，守卫身份后调用页面现有的同候选人加载流程。
- 加入候选人身份、绘制批次和页面指纹校验，关闭或切换时中止，避免旧资料混入。
- 构建产物已同步到用户实际加载的 release 目录；提供 release/wohu-talent-0.2.0.zip。用户需在 Edge 扩展管理重新加载插件，再刷新 BOSS。
- 本次仅开发浏览器插件。覆盖当前 BOSS 推荐候选人详情；图片、视频、附件内容及仍折叠的文字不能承诺全量，页面会提示。没有开发 OCR、后端或飞书，也没有验证外部系统对新增字段的接收。

## 验证情况

- 真实登录页面以最终 MAIN 构建进行采集验证，共 3 位候选人：A 为 3 段工作、1 段教育、2 段项目，2385 字符绘制原文，3 段职责与运行时全文核对一致，项目说明均补齐；B 为短简历，619 字符原文，完整区域判断通过；C 为 5 段工作、2 段教育，912 字符原文，5 段职责均存在。最终打包后复测 C，通过，四来源均有证据且无冲突。
- A/B 身份和原文对应，返回 A 后身份一致；采集中切换返回 PAGE_NOT_READY，不返回混合记录；关闭详情后返回 UNSUPPORTED_PAGE。临时容器高度恢复。
- 网络实测：通过页面自身翻页加载新列表，观察到 15 条投影缓存；打开其中一位候选人，采集结果包含 Network 证据。插件不自行翻页。
- npm test：13 项通过；npm run package：类型检查、生产构建和打包通过。新增验证复用现有 Node 测试，没有引入测试框架、Fixture 或 Mock。
- 正式 release 目录在独立 Chromium 中加载为 0.2.0，状态 ENABLED，安装、manifest 和运行错误列表为空。实际 popup 页面加载无脚本错误、无横向溢出，并检查截图。用户已登录 Edge 中验证的是同一 MAIN 采集代码；尚未完成用户重新加载后的真实弹窗端到端验收，不能将两者混称。
- ZIP 共 14 个文件，逐项 CRC 和 dist 内容比对通过；release 散装文件与 dist 哈希全部一致。未将真实候选人资料写入项目或安装包。
